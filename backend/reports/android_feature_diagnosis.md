## 1. Executive Summary & Checkpoint Determination

A comprehensive diagnosis of the legacy Android Feature Analysis tool (`POST /api/ml/analyze-android`) and its underlying Random Forest model (`android-random-forest-grouped-sklearn-1.8.0-v1`) was conducted.

### Key Diagnostic Findings:
1. **Root Cause of Legacy Failure:**
   - **Estimator Incompatibility:** The original model (`android_random_forest_grouped.joblib`) was serialized using scikit-learn 1.9.1. When loaded in the production FastAPI runtime running scikit-learn 1.8.0, unpickling raised an `InconsistentVersionWarning`. The defensive model loader in `android_classifier.py` intercepted this warning and aborted startup with `AndroidModelLoadError`.
   - **Configuration Schema Mismatch:** The legacy configuration (`backend/reports/ml/android_malware/experiment_config.json`) contained `feature_count: null`, which failed schema dimension validation against `len(feature_columns) = 226`.
   - **Runtime Consequence:** Startup failure set `app.state.android_model = None`. Any request to `POST /api/ml/analyze-android` returned `HTTP 503 Service Unavailable` (`"The Android malware classification model is not available."`).
   - **UI Input Barrier:** The frontend form (`AndroidFeatureAnalysis.jsx`) presented an empty JSON textarea requiring 226 exact key-value pairs without a pre-fill mechanism. Submitting empty or malformed inputs resulted in client-side error `"Provide exactly 226 configured features"` or backend `HTTP 422 Unprocessable Content`.
2. **Feature Lineage & APK Extraction Feasibility:**
   - The 226 features originated from Arvind Mahindru's `AndroidDataset.xlsx` (121,189 rows, 1,430 columns).
   - Only **42 direct permission names** (18.58%) and **2 intent actions** (0.88%) can be mapped directly to static manifest declarations in `AndroidManifest.xml` (total: 44 features, **19.47%**).
   - **165 features** (73.01%) are legacy human-readable permission descriptions (`"Default : ... (S)"`, `"Your personal information : ... (D)"`) generated by an undocumented upstream pipeline with unverified mapping to modern AOSP permission identifiers.
   - **17 features** (7.52%) are compound flow/API co-occurrence pairs (`" SMS_MMS__SMS_MMS "`, `" VOIP__VIDEO "`) generated by DroidDissector's proprietary taint/call-graph engine. These cannot be reproduced from static manifest parsing or standard single-pass Dalvik disassembly.
   - **Reference APK Ground Truth Absent:** The dataset authors published only tabular Excel vectors; no matching raw APK binaries were distributed, making sample-for-sample Jaccard parity verification impossible.

### Checkpoint Verdict:
> [!IMPORTANT]
> **CHECKPOINT RESULT: FAILED (< 80% Reproducibility)**  
> With only **44 out of 226 features (19.47%)** reliably extractable from an APK alone, the model falls far short of the ~80% reproducibility threshold.  
> As mandated by project safety instructions: **Stop after Phase 2 (making the legacy tool work with a sample vector and tests) and report findings.** Do not connect the unverified 226-feature model to live APK uploads.

## 4. Extraction Gap Analysis & Checkpoint Evaluation

### 4.1 Positional Sensitivity of the Model
As established in `backend/reports/ml/android_apk_detection/android_model_audit.md`:
- The Random Forest model was fitted directly on a `np.uint8` array without storing feature names in `estimator.feature_names_in_`.
- The trees evaluate threshold splits based strictly on column indices $0 \dots 225$.
- If an extractor defaults unmapped features to `0` (or guesses mappings inaccurately), it introduces severe distribution drift into the tree routing, invalidating model inferences.

### 4.2 Parity Barrier
- Because the dataset authors did not release the APK files corresponding to `AndroidDataset.xlsx`, empirical vector parity cannot be measured.
- The 17 API flow features (7.52%) and 165 description features (73.01%) cannot be extracted with verified accuracy from an APK.
- The total faithful extraction coverage is **19.47%** (44 / 226 features).

### 4.3 Checkpoint Evaluation
- **Target Threshold:** $\ge 80\%$ reproducible features.
- **Observed Reproducibility:** **$19.47\%$**.
- **Action:** Stop after Phase 2. The legacy vector tool will be stabilized with sample vector loading and unit tests for demonstration purposes, but no unverified heuristic bridge will be connected to live APK uploads.
